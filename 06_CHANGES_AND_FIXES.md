# 06 Changes and Fixes

## Scope

This documents the changes made to fix four reported issues in the trading terminal:

1. Live market data was inaccurate / not showing properly.
2. The Buy button didn't reliably work.
3. Buying should fill at the live LTP and then show live, continuously updating P&L.
4. The Sell button should close a position (and support real short-selling).

Root causes were found by reading the actual code (not the aspirational `01`-`05` docs, which describe a larger, partly-unimplemented target state). Several of the issues turned out to be caused by bugs that would affect correctness even after the surface-level restriction was lifted, so those are called out explicitly below.

---

## Issue 1 — Live market data

**Root causes:**
- `Quote` (`backend/app/schemas/market_data.py`) had no `change`, `change_pct`, `prev_close`, `open`, `high`, `low` fields at all. The frontend ticker and the option-chain service both read `quote.change` / `quote.change_pct` — on a Pydantic model without those fields this always showed `0.00%` in the UI and would raise `AttributeError` in the option-chain's DB-fallback code path.
- `backend/app/market_data/upstox.py`'s WebSocket parser only read `fullFeed.marketFF`. The configured instrument keys are `NSE_INDEX`/`BSE_INDEX` (spot indices), whose Upstox V3 feed reports under `fullFeed.indexFF` instead — every live index tick was silently dropped, so the ticker was actually being driven only by a 2-second REST polling fallback with synthetic zero-spread depth.
- `docker-compose.yml` (the documented way to run this project) never passed `MARKET_DATA_SOURCE` / `UPSTOX_*` from the root `.env` into the `api` container at all. Running via `docker compose up` always fell back to the SIMULATOR feed, regardless of what credentials were configured.
- `Quote.is_stale` existed but was never set by anything.

**Fixes:**
- Added `open`/`high`/`low`/`prev_close`/`change`/`change_pct` to `Quote`.
- Fixed the WebSocket parser to also read `indexFF`, so live index ticks stream in real time instead of relying solely on the REST fallback.
- Pull `prev_close` from the feed's OHLC block (and a best-effort REST prime at connect time) so `change`/`change_pct` populate immediately and consistently across both the WS and REST-fallback paths.
- Added staleness detection: if a symbol's REST fallback fails and it hasn't ticked in 5s, its cached quote is flagged `is_stale=True` and rebroadcast so clients can show it.
- Fixed the option-chain DB-fallback path so it uses the new real fields instead of crashing.
- `docker-compose.yml`: added `env_file: ./.env` to the `api` service so Upstox credentials actually reach the container.
- Frontend: the ticker now shows real `change`/`change%`, a stale indicator (red dot) when a feed hasn't ticked recently, and an "updated Xs ago" freshness readout.

**Files:** `backend/app/schemas/market_data.py`, `backend/app/market_data/upstox.py`, `backend/app/market_data/simulator.py`, `backend/app/services/option_chain_service.py`, `docker-compose.yml`, `frontend/src/App.jsx`, `frontend/src/index.css`.

## Issue 2 & 4 — Buy/Sell buttons

**Root causes:**
- The backend hard-rejected any non-BUY order in two places: `order_service.py` (`raise ValueError("Only BUY orders are allowed...")`) and `matching_engine.py` (`if order.side != OrderSide.BUY: reject`).
- The frontend had **no Sell button at all** — the order modal was BUY-only, with a literal "SELLING OPTIONS IS DISABLED" notice, even though `.sell-btn` CSS already existed unused.
- **Crash bug**: `order_service.py` never imported `Decimal`, but `_update_position` uses `Decimal("0.00")` whenever a position is fully closed. Simply removing the BUY-only restriction would have caused every close/flip to fail with `NameError`.
- There was no margin or fund-sufficiency check anywhere — `check_pre_trade` only checked account status.

**Fixes (full short-sell support, not just close-only):**
- Removed the BUY-only restrictions in `order_service.py` and `matching_engine.py`.
- Added the missing `Decimal` import and fixed `_update_position` to return the realized P&L generated by a fill.
- `risk/engine.py`'s `check_pre_trade` is now async and does real checks:
  - **BUY**: rejects if `account.equity - value_of_other_open_longs < cost` ("Insufficient funds").
  - **SELL**: splits the order into "closes an existing long" (always allowed) and "opens/increases a short" (the remainder). The short portion is gated by an approximate margin requirement.
- Margin approximation (new settings in `core/config.py`: `SHORT_MARGIN_PERCENT`, default 15%, and `MIN_MARGIN_PER_LOT`, default ₹30,000): `max(strike * lot_size * 15%, ₹30,000)` per lot. **This is an explicit simplification** — no real NSE SPAN+exposure margin API is available to this platform — but it prevents short selling from silently exceeding account capital.
- Every filled order that produces realized P&L now writes a `LedgerEntry` (model already existed, was unused) for an audit trail.
- Frontend: the order ticket now has a BUY/SELL toggle, and every open position row has a **Close** button that submits the correct opposite-side order for the exact held quantity.

**Files:** `backend/app/services/order_service.py`, `backend/app/execution/matching_engine.py`, `backend/app/risk/engine.py`, `backend/app/services/account_service.py`, `backend/app/core/config.py`, `frontend/src/App.jsx`, `frontend/src/index.css`.

## Issue 3 — Live P&L

**Root causes:**
- **Equity bug**: `pnl_service.py` computed `account.equity = account.current_balance + account.floating_pnl`, omitting `account.realized_pnl`. Realized gains/losses from a closed or reduced position never reached equity, `daily_pnl`, or drawdown — which also silently broke the pass/fail risk checks.
- No live push existed. The frontend already subscribed to `account.{id}.orders/positions/summary/pnl/trades` WebSocket topics and refetched on receipt, but the backend never sent them — P&L only updated once, immediately after the order's own REST call returned, and never again as prices moved.

**Fixes:**
- Fixed the equity formula: `current_balance + realized_pnl + floating_pnl`.
- Added `backend/app/services/broadcast_service.py`: tracks which WebSocket connections are subscribed to which account, and pushes a lightweight refresh signal (`account.{id}.pnl` / `.positions` / `.orders`) whenever a relevant quote ticks (throttled to ~1/second per account) or an order fills. The frontend's existing debounced refetch-on-signal logic picks this up with no transport changes needed.
- `api/market_data.py`'s WebSocket endpoint now registers/unregisters these account-topic subscriptions.

**Files:** `backend/app/services/pnl_service.py`, `backend/app/services/broadcast_service.py` (new), `backend/app/market_data/simulator.py`, `backend/app/market_data/upstox.py`, `backend/app/api/market_data.py`, `backend/app/services/order_service.py`.

## Other cleanup

- `backend/app/api/accounts.py` deduplicated: it had two independent, drifting copies of the summary/position-computation logic (one inline, one in `AccountQueryService`, which was otherwise unused). It now reuses the shared service.
- `backend/pyproject.toml` / new `backend/requirements.txt`: added `aiosqlite`, which is required by the SQLite `DATABASE_URL` the root `.env` is actually configured with, but was never declared as a dependency.

## Testing performed

- New `backend/tests/` (none existed before) with 6 tests covering: BUY fills at LTP and creates a position, closing a long realizes P&L into equity (regression guard for the equity-formula bug), reopening after a full close doesn't crash (regression guard for the missing `Decimal` import), a naked SELL with insufficient margin is rejected, a properly funded SELL opens a short and a later BUY covers it with correct realized P&L, and a BUY beyond available funds is rejected. All 6 pass (`pytest tests/` from `backend/`).
- Full HTTP-level smoke test (login → list accounts → BUY an option at an injected LTP → confirm the position and account summary → move the price → confirm unrealized P&L updates on a plain GET with no new order → SELL to close → confirm realized P&L lands in equity → attempt a naked short → confirm the margin rejection message) — all behaved as expected.
- `npm run build` on the frontend completes cleanly with no errors.

## Known gaps (not part of this fix, called out for awareness)

- **No account/order ownership enforcement.** Any authenticated user can currently query or trade on any `account_id` by guessing/knowing its UUID — this predates these changes and is a larger auth/authorization effort (`get_current_user` exists but isn't wired into the account/order routers).
- The short-sell margin figure is a deliberate simplification, not real NSE SPAN+exposure margin (no such live API is available to this platform).
